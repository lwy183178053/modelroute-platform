# ModelRoute 官方模型种子

## 业务结论

官方模型目录使用随代码发布的版本化 JSON 种子，不在生产环境自动抓取官网。当前版本为 `2026-07-23-v1`，绑定 New API `v1.0.0-rc.21` 和源码提交 `bde9b2f44887d34ec54799ae191d50f97914359e`。

种子只收录同时满足以下条件的模型：

1. 官方页面能核对 API 标识和标准按量 Token 价格。
2. 固定 New API 源码的对应渠道适配器明确列出该 API 标识。
3. 价格可以由已批准的 `len/p/c/cr/cc/cc1h` 分层表达式准确表示。
4. 模型未退役；Preview、限量和临近退役模型只录入目录，默认停用。

## 导入规则

- 新模型创建首个官方价格版本。
- 已存在且厂商、协议、生命周期和当前价格完全一致时跳过。
- 当前价格变化时只追加官方价格版本，不改写历史版本。
- 已存在模型的厂商、协议或生命周期与种子冲突时终止导入。
- 全部模型处理成功后，写入 `official_model_seed_version` 和 `official_model_seed_digest`。
- 中途失败后可重复执行；已成功写入且价格未变化的模型会被跳过。

## 部署与手工执行

`model-seed` 是 `tools` profile 下的一次性服务，不随 API、Worker 和网关常驻运行。`deploy/scripts/deploy.sh` 的顺序固定为：

1. 校验并构建镜像。
2. 启动 PostgreSQL、Redis 和 New API。
3. 执行一次 `model-seed`。
4. 启动其余常驻服务。

需要在受控环境重新核对幂等性时执行：

```bash
docker compose --env-file .env --profile tools run --rm model-seed
```

命令会通过 New API 原生登录读取唯一管理员账号，只接受 `.env` 中配置的有效管理员；管理员密码和 New API 会话均不写入种子、日志或 Git。

## 验证与回滚

```bash
cd apps/api
go test -count=1 ./internal/modelseed ./cmd/seed-models

cd ../..
python -m unittest discover -s deploy/tests -p 'test_*.py'
docker compose --env-file .env.example --profile tools config --quiet
```

真实 PostgreSQL 幂等测试使用 `MODELROUTE_TEST_DATABASE_URL`；固定源码交集测试使用 `NEW_API_RC21_SOURCE_DIR`。生产发布前还必须执行双数据库备份和恢复演练。

未发布生产时，可直接回退代码提交。生产已执行种子后，代码回退不会删除模型和价格历史；若必须恢复发布前目录状态，应使用同一时间点的平台库与 New API 库备份，不手工删除价格版本。
