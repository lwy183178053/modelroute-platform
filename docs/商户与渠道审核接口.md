# ModelRoute V2 商户与单模型渠道审核

## 业务边界

- New API 继续负责账号、余额、API 密钥、模型转发和原生计费。
- 平台数据库记录商户身份、单模型渠道审核、渠道归属和自动检测结果。
- 唯一管理员拥有“ModelRoute 官方”商户，使用与普通商户完全相同的商户中心和商户接口，只额外显示管理后台。
- 所有商户和管理员接口都在服务端验证会话、账号状态和身份；前端导航不是权限边界。

## 商户申请

普通用户先选择管理员已上架的标准模型，填写渠道名、公开 HTTPS 基础地址和密钥，通过 `POST /api/merchant/channel-tests` 发送 `hi`。检测成功后得到 15 分钟有效的 `test_receipt`，再与商户名称、网站和业务说明一起提交申请。

同一用户同时只允许一条进行中的申请。已有有效商户不能重复申请；商户身份被撤销后可重新申请。唯一管理员不需要普通商户申请记录。

## 渠道检测

- 一条渠道只绑定一个 `canonical_model_id`，没有渠道类型或多模型数组。
- 平台按模型厂商依次尝试原生适配器和 OpenAI 兼容适配器，并在 New API 中创建一次性临时渠道发送 `hi`。
- 临时渠道在检测结束后立即删除，成功响应返回适配器、能力、延迟和短期凭证。
- 检测凭证绑定用户、模型、规范化基础地址和密钥指纹；过期或任一字段变化都必须重新检测。
- 随机检测凭证只保存 SHA-256 摘要，检测保存与提交消费共用同一摘要实现；渠道密钥仍使用独立的 HMAC-SHA256 指纹。
- 临时检测密钥只存在于请求内存，检测记录不保存密钥正文。

## 审核流程

1. 商户提交时，平台加密保存待审密钥，并消费对应检测凭证。
2. 管理员点击验证后，平台重新解密待审密钥并再次发送 `hi`。
3. 管理员复检结果必须与商户自测适配器一致。
4. 验证通过后管理员批准，平台通过 New API 原生接口创建正式单模型渠道。
5. 平台事务写入渠道归属和健康初始状态，并清除待审密钥密文。
6. 创建或平台落库失败时删除刚创建的 New API 渠道，审核记录保持可重试状态。
7. 驳回时清除待审密钥正文并保留审核记录和原因。

管理员审核与商户新增渠道使用同一流程。审核通过后的渠道公共响应只返回标准模型、自动适配器和健康元数据，不返回 New API 渠道类型、内部模型数组、密钥、密文或完整指纹。

## 密钥生命周期

- 待审密钥使用 `PLATFORM_ENCRYPTION_KEY` 进行 AES-256-GCM 加密，并生成 HMAC-SHA256 指纹。
- 管理员复检时只在服务内存短暂解密，调用后覆盖明文字节。
- 正式渠道只保留缩短指纹、自动适配器和 New API 渠道编号。
- New API 管理会话、平台加密主密钥和商户密钥均不进入浏览器、Git、日志或文档。

## 接口

用户和商户：

- `POST /api/merchant/channel-tests`
- `GET /api/merchant/application`
- `POST /api/merchant/application`
- `GET /api/merchant/channels`
- `POST /api/merchant/channels`

管理员：

- `GET /api/admin/merchant-applications`
- `GET /api/admin/merchant-applications/{id}`
- `POST /api/admin/merchant-applications/{id}/verify`
- `POST /api/admin/merchant-applications/{id}/approve`
- `POST /api/admin/merchant-applications/{id}/reject`
- `GET /api/admin/merchants`
- `POST /api/admin/merchants/{id}/status`
- `GET /api/admin/channel-reviews`
- `POST /api/admin/channel-reviews/{id}/verify`
- `POST /api/admin/channel-reviews/{id}/approve`
- `POST /api/admin/channel-reviews/{id}/reject`
- `GET /api/admin/channels`

验证、批准、驳回、撤销和恢复均写入平台审计日志。

## 运行配置与验证

生产环境必须设置 Base64 编码的 32 字节 `PLATFORM_ENCRYPTION_KEY`。该密钥必须与平台数据库备份共同受控保管。

本地 Go 测试覆盖检测凭证生成与消费摘要一致性、凭证伪造、过期、密钥变化、临时渠道清理、管理员复检、单模型响应和商户隔离。生产部署后执行：

```sh
deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz
```

线上脚本只使用一次性普通用户验证权限和密钥不回显，不导入虚假正式渠道。
