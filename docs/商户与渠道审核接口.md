# ModelRoute V2 商户申请与逐模型渠道接口

## 业务边界

- 普通用户先申请商户身份，成为商户后才能创建渠道。
- 渠道只保存厂商、名称、基础地址、密钥指纹和核心渠道编号，本身不保存审核、启停、冷却或健康状态。
- 健康状态保存在“渠道 + 模型”绑定上，同一渠道的不同模型可以同时处于不同状态。
- 唯一管理员使用与普通商户相同的商户中心，只额外拥有管理后台的渠道查看和删除权限。
- 所有商户和管理员接口都在服务端验证会话、账号状态和身份，前端导航不是权限边界。

## 商户申请

普通用户只提交商户名称、商户介绍和网站地址。管理员核对资料后直接通过或驳回，不在商户申请阶段填写、同步或检测渠道。审核通过后创建商户资料，名称和网站只读，商户介绍可通过 `PUT /api/merchant/profile` 修改。

同一用户同时只允许一条进行中的申请。待审核申请和有效商户都会占用全局唯一商户名称；申请驳回或删除后释放名称。唯一管理员不需要普通商户申请记录。

## 渠道创建与同步

1. 商户选择 `provider`：OpenAI、Anthropic、Gemini、DeepSeek、Qwen 或 Moonshot，并填写渠道名、公开 HTTPS 基础地址和密钥。
2. `POST /api/merchant/channel-models/sync` 使用本次请求中的临时配置读取上游模型，只返回厂商和规范化名称同时匹配的平台模型，以及该厂商尚未收录的型号。
3. `POST /api/merchant/channels` 会在服务端重新同步，随后直接创建正式核心渠道和平台渠道记录，不创建待审核记录。
4. 每个已匹配模型写入独立绑定，初始状态为 `pending`。未收录模型只展示同步结果，不写入正式绑定，不参与上架和路由。
5. 核心渠道或平台落库任一步失败时删除本次创建的核心渠道，避免半成品。

OpenAI、DeepSeek、Qwen 和 Moonshot 使用 OpenAI 兼容适配；Anthropic 与 Gemini优先尝试原生适配，失败后回退 OpenAI 兼容适配。适配结果只在服务端使用，商户、用户和管理员页面均不展示协议或内部适配器。

商户可通过 `POST /api/merchant/channels/{id}/models/sync` 重新读取已创建渠道的上游模型。新匹配的绑定仍从 `pending` 开始，必须逐模型检查成功后才可使用。

## 逐模型检查

- 只保留 `POST /api/merchant/channels/{id}/models/{binding_id}/check`，且只能检查当前商户自己的渠道模型。
- 文本模型发送 `hi`，图片模型使用核心图片检测入口。
- 检查成功后模型变为 `healthy`，清零真实失败次数、自动检查失败次数、下次检查时间和旧错误。
- 商户主动检查失败后模型变为 `error`，不会进入模型市场或路由；商户可再次检查，成功后恢复。
- 不提供渠道批量检查、管理员复检、批准或驳回接口。管理员只查看逐模型状态和删除渠道。

商户和管理员渠道列表都不展开模型名称。商户使用“管理模型（数量）”打开弹窗并逐项检查；管理员使用“查看模型（数量）”打开只读弹窗。弹窗显示模型 ID、具体模型、状态、真实失败次数、自动检查失败次数、下次检查、最后检查、耗时和错误。

## 删除与密钥边界

- 商户只能删除自己的渠道，管理员可以删除任意渠道。
- 删除渠道采用归档，`deleted_at` 记录删除时间，历史调用关联继续保留；归档渠道及其模型立即退出上架、市场和路由。
- 上游密钥只在创建请求和核心服务调用期间存在于平台内存。平台正式记录只保留缩短指纹，不保存可恢复正文。
- 核心管理会话、平台加密主密钥和商户密钥均不进入浏览器响应、Git、日志或文档。

## 接口

用户和商户：

- `GET /api/merchant/application`
- `POST /api/merchant/application`
- `GET /api/merchant/profile`
- `PUT /api/merchant/profile`
- `POST /api/merchant/channel-models/sync`
- `GET /api/merchant/channels`
- `POST /api/merchant/channels`
- `POST /api/merchant/channels/{id}/models/sync`
- `POST /api/merchant/channels/{id}/models/{binding_id}/check`
- `DELETE /api/merchant/channels/{id}`

管理员：

- `GET /api/admin/merchant-applications`
- `GET /api/admin/merchant-applications/{id}`
- `POST /api/admin/merchant-applications/{id}/approve`
- `POST /api/admin/merchant-applications/{id}/reject`
- `GET /api/admin/users?type=merchant`
- `POST /api/admin/users/{id}/merchant-status`
- `GET /api/admin/channels`
- `DELETE /api/admin/channels/{id}`
- `GET /api/admin/channel-logs`

## 验证

本地测试覆盖厂商模型隔离、服务端重新同步、正式渠道创建补偿、跨商户权限、逐模型检查、手动恢复、归档删除，以及管理员只读边界。生产部署后继续执行：

```sh
deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz
```

线上脚本只使用一次性普通用户验证商户申请和权限，不创建虚假正式渠道，也不输出渠道密钥。
