# ModelRoute V2 商户与多模型渠道审核

## 业务边界

- 核心服务继续负责账号、余额、API 密钥、模型转发和原生计费。
- 平台数据库记录商户身份、多模型渠道审核、渠道归属和逐模型检测结果。
- 唯一管理员拥有“ModelRoute 官方”商户，使用与普通商户完全相同的商户中心和商户接口，只额外显示管理后台。
- 所有商户和管理员接口都在服务端验证会话、账号状态和身份；前端导航不是权限边界。

## 商户申请

普通用户只提交商户名称、商户介绍和网站地址。管理员核对资料后直接通过或驳回，不在商户申请阶段填写、同步或检测渠道。审核通过后，用户获得商户身份，再从商户中心提交渠道。

同一用户同时只允许一条进行中的申请。已有有效商户不能重复申请；商户身份被撤销后可重新申请。唯一管理员不需要普通商户申请记录。

商户设置读取 `GET /api/merchant/profile`。商户名称和网站保持审核结果且只读，商户介绍可通过 `PUT /api/merchant/profile` 修改。

## 渠道同步

- 商户先选择 `provider`：OpenAI、Anthropic、Gemini、DeepSeek、Qwen 或 Moonshot，再填写渠道名、公开 HTTPS 基础地址和密钥。
- `POST /api/merchant/channel-models/sync` 使用临时上游配置调用核心服务的原生模型同步接口，返回已匹配和平台未收录模型。
- 平台只匹配管理员目录中厂商与规范化名称同时一致的模型；其他已知厂商模型直接过滤，当前厂商未收录型号只能查看。
- OpenAI、DeepSeek、Qwen 和 Moonshot 使用 OpenAI 兼容适配；Anthropic 与 Gemini 优先尝试原生适配，失败后回退 OpenAI 兼容适配。适配结果仅在服务端保存。
- 商户可填写常见的 `/v1` 或 `/v1beta` 结尾地址；平台保存原值，仅在调用核心服务时去掉协议版本后缀，避免重复拼接路径。
- 商户正式提交渠道时，服务端重新同步，避免提交过期或伪造的模型清单。
- 审核期间密钥使用平台主密钥加密保存；公开响应只返回缩短指纹。

## 审核流程

1. 商户同步模型后提交渠道，服务端重新同步并加密保存待审密钥。
2. 管理员点击“验证”后，接口立即返回 `202` 和 `verifying`；平台在后台重新解密待审密钥并顺序检查全部已匹配模型，文本模型发送 `hi`，图片模型使用图片检测入口。页面轮询审核记录直到验证结束，长时间检测不占用浏览器请求连接。
3. 每个模型分别保存成功、失败、耗时和脱敏后的错误。至少一个模型成功时审核进入“已验证”，全部失败时恢复为待审核。
4. 管理员批准后，平台通过核心服务原生接口创建只包含验证成功模型的正式渠道，不重复测试第一个模型；未收录、未检查和检查失败的型号不会进入路由。
5. 平台事务写入渠道归属和健康初始状态，并清除待审密钥密文。
6. 创建或平台落库失败时删除刚创建的核心渠道，审核记录保持可重试状态。
7. 驳回时清除待审密钥正文并保留审核记录和原因。

管理员审核与商户新增渠道使用同一流程。审核通过后的渠道公共响应返回厂商、模型匹配状态和健康元数据，不返回核心渠道编号、密钥、密文或完整指纹。自动适配结果仅用于服务端创建核心渠道，商户、用户和管理员页面均不展示模型协议或内部适配器。

管理后台和商户中心的渠道列表不直接展开模型名称，统一显示“查看模型（数量）”。弹窗展示匹配状态、检查状态、耗时和错误；管理员可在弹窗中重新检查单个已匹配模型，商户弹窗保持只读。正式渠道弹窗展示实际导入的型号。

批量验证最长运行 15 分钟。浏览器连接关闭或网关超时不会取消后台任务；任务完成后审核状态变为“已验证”或恢复为“待审核”，页面根据逐模型结果统计成功和失败数量。单模型检查仍为同步短请求。

## 密钥生命周期

- 待审密钥使用 `PLATFORM_ENCRYPTION_KEY` 进行 AES-256-GCM 加密，并生成 HMAC-SHA256 指纹。
- 管理员复检时只在服务内存短暂解密，调用后覆盖明文字节。
- 正式渠道只保留缩短指纹、自动适配器和核心渠道编号。
- 核心服务管理会话、平台加密主密钥和商户密钥均不进入浏览器、Git、日志或文档。

## 接口

用户和商户：

- `POST /api/merchant/channel-models/sync`
- `GET /api/merchant/application`
- `POST /api/merchant/application`
- `GET /api/merchant/profile`
- `PUT /api/merchant/profile`
- `GET /api/merchant/channels`
- `POST /api/merchant/channels`
- `DELETE /api/merchant/channel-reviews/{id}`
- `POST /api/merchant/channels/{id}/models/sync`
- `POST /api/merchant/channels/{id}/status`
- `DELETE /api/merchant/channels/{id}`

管理员：

- `GET /api/admin/merchant-applications`
- `GET /api/admin/merchant-applications/{id}`
- `POST /api/admin/merchant-applications/{id}/approve`
- `POST /api/admin/merchant-applications/{id}/reject`
- `GET /api/admin/users?type=merchant`
- `POST /api/admin/users/{id}/merchant-status`
- `GET /api/admin/channel-reviews`
- `POST /api/admin/channel-reviews/{id}/verify`
- `POST /api/admin/channel-reviews/{id}/model-tests`
- `POST /api/admin/channel-reviews/{id}/approve`
- `POST /api/admin/channel-reviews/{id}/reject`
- `GET /api/admin/channels`
- `POST /api/admin/channels/{id}/status`
- `DELETE /api/admin/channels/{id}`
- `GET /api/admin/channel-logs`

验证、批准、驳回、撤销和恢复结果保存在对应申请、渠道和用户扩展记录中。平台不保留独立操作记录；等待审核的渠道记录可撤销，驳回记录可删除，已审核渠道通过正式渠道接口管理。成功消费永久保存在统一调用事实表中。

## 运行配置与验证

生产环境必须设置 Base64 编码的 32 字节 `PLATFORM_ENCRYPTION_KEY`。该密钥必须与平台数据库备份共同受控保管。

平台启动时会为唯一管理员幂等开启内部“允许测试未配置公开价格模型”设置，只修改该管理员账号并保留已有邮件通知、额度阈值和 IP 日志设置。该设置只用于渠道审核检测，不给公开模型写零价格，也不影响普通用户计费。

本地 Go 测试覆盖多模型同步、匹配与未收录分类、服务端重新同步、管理员逐模型检查、渠道启停删除和商户隔离。生产部署后执行：

```sh
deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz
```

线上脚本只使用一次性普通用户验证权限和密钥不回显，不导入虚假正式渠道。
