# ModelRoute 部署运行手册

## 部署目录

生产目录固定为 `/opt/modelroute-platform`。`releases/<12位Git哈希>/` 保存不可变发布归档，`current` 原子指向当前发布；`.env`、运行数据和备份分别位于 `shared/.env`、`shared/data/` 和 `shared/backups/`，发布目录只建立软链接。

## 本地同构开发

本地项目名固定为 `modelroute-dev`，数据只写入独立命名卷，不连接或复制生产数据库。首次启动会生成被 Git 忽略的 `.env.dev`、初始化本地唯一管理员、执行迁移和模型种子：

```powershell
deploy\scripts\dev.ps1 up
```

- `dev.ps1 up`：启动 PostgreSQL、Redis、固定 New API、Air 热更新 API/Worker 和 Vite HMR，页面为 `http://127.0.0.1:57723/`。
- `dev.ps1 down`：停止容器但保留开发卷。
- `dev.ps1 logs`：跟随 API、Worker、New API 和前端日志。
- `dev.ps1 verify`：验证页面、存活、就绪、模型鉴权和 `dev` 版本。
- `dev.ps1 rebuild`：依赖或开发镜像变化后重建 Go 开发镜像。
- `dev.ps1 reset -ConfirmReset`：只删除 `modelroute-dev` 命名卷并重新初始化。
- `dev.ps1 preflight`：短暂停止热更新容器，使用生产 Dockerfile、Nginx 和固定依赖镜像在 `127.0.0.1:28100` 验收，结束后恢复 `57723`。

生产 Compose 和 Dockerfile 默认使用 Docker Hub 官方名称及固定摘要。本地开发、同构预检和发布构建使用 DaoCloud 的同摘要镜像，只改变下载入口，不改变镜像内容；`.env.dev` 中的凭据和镜像覆盖均不进入 Git。

## 不可变镜像发布

平台 API、Worker 和模型种子共用一个平台镜像，前端与 Nginx 共用一个网关镜像。GHCR 包保持私有，标签固定为 Git 的 12 位提交哈希，103 最终按摘要拉取：

```text
ghcr.io/lwy183178053/modelroute-platform-api:<HASH>
ghcr.io/lwy183178053/modelroute-platform-gateway:<HASH>
```

本机先使用具备 `write:packages` 的凭据执行 `docker login ghcr.io`；103 只使用 `read:packages` 凭据登录。凭据通过标准输入传给 Docker，不写入仓库、发布归档、文档正文或终端历史。

提交已推送且工作区干净后执行：

```powershell
deploy\scripts\release.ps1
deploy\scripts\release.ps1 -Deploy103
```

不带参数时执行 Go、前端、部署脚本、Compose 和本地同构验收，不推送镜像。`-Deploy103` 还会构建 `linux/amd64` 镜像、推送 GHCR、记录摘要、上传 Git 归档和清单，并由 103 拉取摘要镜像。新发布先完成内网验收，再原子切换 `current` 并执行公网、账号、商户、路由、支付、提现、运营和压力验收；任一步失败都会保持或恢复上一指针并重新启动上一发布镜像。

## 首次部署

1. 把发布归档解压到 `/opt/modelroute-platform`。
2. 创建权限为 `600` 的 `.env`，所有密码和密钥使用随机十六进制值。
3. 执行 `deploy/scripts/deploy.sh`。
4. 执行 `deploy/scripts/verify.sh http://127.0.0.1:28100`。
5. 备份 `/etc/caddy/Caddyfile`，追加 `deploy/caddy/aggregate.Caddyfile`。
6. 执行 `caddy validate --config /etc/caddy/Caddyfile`，验证通过后执行 `systemctl reload caddy`。
7. 执行 `deploy/scripts/verify.sh https://aggregate.lwylink.xyz`。
8. 设置 `ADMIN_PASSWORD_FILE` 后执行 `deploy/scripts/verify-accounts.sh https://aggregate.lwylink.xyz`，验证账号、管理员和临时密钥契约。
9. 执行 `deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz`，验证商户申请、权限、列表和密钥清除契约。
10. 执行 `deploy/scripts/verify-routing.sh https://aggregate.lwylink.xyz`，验证单模型路由、单厂商密钥、多模型绑定边界、公开模型列表和未授权模型错误。
11. 执行 `deploy/scripts/verify-payments.sh https://aggregate.lwylink.xyz`，验证支付权限、浏览器返回页和无效回调拦截。
12. 执行 `deploy/scripts/verify-withdrawals.sh https://aggregate.lwylink.xyz`，只读验证提现列表、商户余额、接口权限和敏感字段边界。
13. 执行 `deploy/scripts/verify-operations.sh https://aggregate.lwylink.xyz`，只读验证用量、运营总览、设置、兑换码、任务和渠道列表。
14. 执行 `REQUESTS=200 CONCURRENCY=10 deploy/scripts/load-test.sh http://127.0.0.1:28100`，验证只读健康入口并发和 P95。

发布目录名必须使用对应 Git 提交的 12 位短哈希。部署脚本会解析 `current` 软链接的真实目录并把该目录名注入 `/api/version`，用于核对线上版本和回滚点。

部署脚本会先启动 PostgreSQL、Redis 和 New API，再执行一次 `tools` profile 下的 `model-seed`，最后启动 API、Worker 和网关。种子失败会立即终止发布，不会继续启动新版本外围服务；详细目录和幂等规则见《官方模型种子.md》。

执行第 `000011_provider_model_routes.sql` 号迁移前，部署脚本会读取平台 `token_bindings` 中的旧用户 Token ID，先从核心服务删除这些用户 Token，再由模型种子任务执行迁移。迁移会清空旧路由和用户密钥绑定，再建立“单厂商密钥 + 单模型路由”结构；用户需重新创建路由和 API 密钥。内部服务令牌不在旧用户 Token 清单中，不会被删除。历史 `routing_decisions` 与统一调用记录继续保留，原密钥和路由外键在清理时置空，避免删除历史请求审计数据。

## 本地交互预览默认配置

本地 `data/ui-preview/vite.config.mjs` 支持通过进程环境预置开发用上游和易支付配置，变量名如下：

```dotenv
MODELROUTE_PREVIEW_UPSTREAM_BASE_URL=https://上游地址
MODELROUTE_PREVIEW_UPSTREAM_KEY=<本地受限密钥>
MODELROUTE_PREVIEW_UPSTREAM_TYPE=openai_compatible
MODELROUTE_PREVIEW_EASYPAY_GATEWAY=https://支付网关
MODELROUTE_PREVIEW_EASYPAY_PID=<本地商户号>
MODELROUTE_PREVIEW_EASYPAY_KEY=<本地受限密钥>
```

预览页面打开“提交新渠道”时会自动填充上游地址和类型；“一键获取模型”由预览服务端读取密钥请求上游 `/v1/models`，浏览器只接收匹配结果，不接收密钥。`/api/models` 和管理后台模型定价页直接读取当前完整模型种子，不使用精简演示列表。管理支付设置只返回商户号掩码和已配置状态。上述变量只用于本地预览，不进入 Git、文档正文、截图或日志；正式部署仍从受限 `.env` 和管理页面配置。

## V2 开发数据重置

V2 基线只用于空库。开发环境直接覆盖时，在新 Git 哈希发布目录中链接共享 `.env` 和 `data`，并指定现有受限 SMTP 设置文件后执行：

```sh
SMTP_OPTIONS_FILE=/opt/modelroute-platform/shared/backups/<已有目录>/newapi-smtp-options.json \
CONFIRM_V2_RESET=MODELROUTE_V2_RESET_103 deploy/scripts/reset-v2-data.sh
```

脚本固定执行以下闭环：

1. 校验主机绑定 `38.34.191.103`、发布目录位于 `/opt/modelroute-platform/releases/`、数据真实路径为 `/opt/modelroute-platform/shared/data`，Compose 项目名为 `modelroute`。
2. 在停止服务前完成 Compose 配置检查和镜像构建，不创建新备份，也不执行恢复演练。
3. 停止且只停止 `modelroute` Compose 项目，直接清理 `postgres`、`redis`、`new-api`、`new-api-logs` 四个固定数据子目录。
4. 启动基础服务；先用不超过 12 字符的临时用户名完成 New API 原生 `/api/setup`，再通过原生用户更新接口改为 `NEW_API_ADMIN_USERNAME`，用目标用户名重新登录后从指定文件恢复 SMTP 选项，执行 V2 模型种子并启动全部服务。若流程在 setup 与改名之间中断，重跑初始化脚本会识别临时根账号并继续改名。
5. 验证本地网关、两份 V2 迁移、`2026-07-23-v2` 种子版本、21 个有效模型和 MiniMax 为零。

脚本执行后再原子切换 `current`，并完成本文的公网专项验收。本次是开发数据直接覆盖，异常时修复后重跑同一脚本，不恢复旧平台库、New API 库或 Redis。

宿主机已有 Caddy 负责公网证书。Caddy 自动签发的公有证书满足 Cloudflare Full Strict，不需要让 ModelRoute 容器接触证书私钥。

账号服务启用后，`.env` 还必须配置以下非密钥项：

```dotenv
PUBLIC_ORIGIN=https://aggregate.lwylink.xyz
SESSION_COOKIE_NAME=modelroute_session
SESSION_COOKIE_SECURE=true
SESSION_TTL=24h
NEW_API_REQUEST_TIMEOUT=30s
NEW_API_ADMIN_USERNAME=3180615598@qq.com
NEW_API_ADMIN_PASSWORD=<受限管理员密码>
PLATFORM_ENCRYPTION_KEY=<Base64 编码的 32 字节随机密钥>
```

`PUBLIC_ORIGIN` 必须与浏览器实际来源完全一致。生产环境使用 HTTPS 时，`SESSION_COOKIE_SECURE` 保持为 `true`。

`PLATFORM_ENCRYPTION_KEY` 用于易支付密钥和支付宝收款账号的 AES-256-GCM 加密。可使用 `openssl rand -base64 32` 生成；生产启用后必须与数据库备份一同受控保管，不得进入发布目录、Git 或终端记录。

`NEW_API_ADMIN_USERNAME` 和 `NEW_API_ADMIN_PASSWORD` 供平台服务端同步价格、创建多模型渠道、执行逐模型检查和维护探测令牌。该用户名也是 ModelRoute 唯一管理员身份边界；平台启动时会核对账号编号、用户名、状态和角色，并幂等创建其直属“ModelRoute 官方”商户。任一核对失败时 API 与 Worker 均停止启动，避免出现管理员页面可见但没有真实商户编号的状态。凭据只进入权限为 `600` 的共享 `.env`，前端和平台接口均不返回。

易支付 PID、KEY、支付方式和人民币充值范围不进入 `.env`。管理员登录 ModelRoute 后在“管理后台 -> 支付与充值”发布配置版本，KEY 由 `PLATFORM_ENCRYPTION_KEY` 加密保存。公开上线前必须轮换聊天、工单或终端记录中出现过的支付凭据；轮换后只在管理页面输入一次，文档、Git、部署归档和验收输出均不记录正文。

## 邮件设置

注册验证码和密码重置邮件复用既有 SMTP 服务，但配置落点是 New API 原生系统设置，不是 ModelRoute `.env`：

1. 管理员登录 New API 内网管理接口。
2. 通过原生 `/api/option/` 接口设置 SMTP 主机、端口、账号、发件人、TLS 模式和密码，并启用邮箱验证。
3. 分别完成一次注册验证码和密码重置邮件实发测试。
4. 删除测试账号，确认没有测试用户残留。

SMTP 密码由 New API 设置数据库保存，因此 `newapi.dump` 属于敏感备份，必须放在受限目录中。终端输出、Git、平台接口和浏览器均不得出现密码正文。

## 生产验收

每次发布至少执行以下检查：

1. 在宿主机执行 `deploy/scripts/verify.sh http://127.0.0.1:28100`。
2. 执行 `deploy/scripts/verify.sh https://aggregate.lwylink.xyz`。
3. 设置 `ADMIN_PASSWORD_FILE` 后执行 `deploy/scripts/verify-accounts.sh https://aggregate.lwylink.xyz`。
4. 执行 `deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz`。
5. 执行 `deploy/scripts/verify-routing.sh https://aggregate.lwylink.xyz`。
6. 执行 `deploy/scripts/verify-payments.sh https://aggregate.lwylink.xyz`。
7. 执行 `deploy/scripts/verify-withdrawals.sh https://aggregate.lwylink.xyz`。
8. 执行 `deploy/scripts/verify-operations.sh https://aggregate.lwylink.xyz`。
9. 执行 `REQUESTS=200 CONCURRENCY=10 deploy/scripts/load-test.sh http://127.0.0.1:28100`。
10. 确认重置后的平台迁移只包含 `000001_v2_baseline.sql`、`000002_multimodel_channels.sql` 和 `000003_offer_deleted_status.sql`，多模型渠道、唯一模型价格、人民币支付、自动入账、公告和文本/图片价格表均存在。
11. 确认 `platform_runtime_metadata` 中的 `official_model_seed_version` 为 `2026-07-23-v2`，共 21 个有效模型、MiniMax 为 0，且重复执行种子不新增价格版本。
12. 确认 `/api/version` 与发布目录和 Git 提交一致。
13. 检查 Worker 日志中没有持续的结算同步异常，并核对 `settlement_sync_state` 水位正在推进。
14. 在服务稳定后的新时间窗口检查 Caddy 日志，避免把容器重启窗口内的 `context canceled` 误判为持续故障。
15. 确认 `api.lwylink.xyz` 和 `sdk.lwylink.xyz` 仍正常返回，且 New API、PostgreSQL、Redis 没有宿主机监听端口。

上述账号、商户、路由、支付、提现和运营脚本默认使用唯一管理员 `3180615598@qq.com`，密码只从受限文件读取。账号与路由专项验收只物理清理自身生成且名称符合约定的测试 Token；路由专项验收还会创建临时单模型路由，读取服务器内临时测试密钥执行真实 `/v1/models` 与模型调用，并核对公开密钥指纹匹配。多模型渠道专项验收使用临时上游配置完成模型同步、匹配与未收录分类、逐模型检查、批准、启停和删除；结束或中断时清理平台审核、模型绑定和核心测试渠道，不保留渠道密钥正文。

`/api/health/ready` 会真实检查数据库、Redis 和 New API，但同一秒内的并发请求共享一次检查结果。压力测试后还应检查 New API 日志，确认验收窗口内 `/api/status` 没有 `429`；若出现限流，不得把稍后恢复的单次 `200` 视为压力测试通过。

在有 Chrome 的受控运维机上执行真实生产页面检查，管理员凭据只通过受限文件传入：

cd apps/web
$env:ADMIN_PASSWORD_FILE = 'C:\受限目录\bootstrap-admin.txt'

脚本使用浏览器同源请求登录，不输出用户名或密码；分别以 `1440x1000` 和 `390x844` 检查公告入口、桌面头像跳转、管理员共用商户工作区、模型绝对价格弹窗、页面横向溢出、运行时错误和 `5xx`。截图写入 `PRODUCTION_SCREENSHOT_DIR`，不得提交到 Git。本地 `npm run capture` 生成的 `apps/web/artifacts/` 同样属于可再生产物并由 Git 忽略。移动端顶部头像按响应式设计隐藏，控制台通过折叠菜单进入；控制台侧栏在窄屏下使用两列换行，五个入口应同时可见，不依赖横向滚动定位。

## 日常更新

1. 在本地热更新环境完成修改和聚焦验证，执行 `dev.ps1 preflight` 确认生产同构镜像。
2. 提交并推送当前分支，确认工作区干净。
3. 执行 `deploy/scripts/release.ps1 -Deploy103`；脚本负责测试、镜像推送、摘要清单、远端安装、验收和失败回滚。
4. 发布后检查稳定窗口日志和三个既有 HTTPS 域名，确认 101、102 项目未受影响。
5. 涉及不兼容数据库变更时仍需在发布前按对应任务要求处理数据；镜像回滚不替代数据库恢复。

## 数据恢复

恢复脚本会停止 API、Worker 和 New API，并清理目标数据库后导入备份。执行前必须设置 `CONFIRM_RESTORE=MODELROUTE_RESTORE`，且必须先保留当前数据库的新备份。

日常发布先执行 `verify-backup-restore.sh`：该脚本只恢复到自动生成的临时数据库，不停止服务、不覆盖生产库，并在验证后删除临时库。只有正式恢复才使用 `restore.sh`。

## 版本回滚

`rollback-release.sh` 要求显式确认变量和目标 Git 哈希，并验证目标真实位于 `/opt/modelroute-platform/releases/`。脚本先部署和验收目标版本，再原子切换 `current`；若部署或验收失败，会保留当前指针并尝试恢复当前发布。该脚本只负责代码与容器版本，涉及不兼容数据库迁移时仍按发布前备份恢复数据。

## 隔离要求

- Compose 项目名固定为 `modelroute`。
- 网关仅绑定 `127.0.0.1:28100`。
- New API、PostgreSQL 和 Redis 均不发布宿主机端口。
- Caddy 修改必须先备份、验证，再平滑 reload。
- Caddy 配置备份统一保存在 `/etc/caddy/backups/`。
- Sub2API 与 SDK 的容器、目录、数据库、端口和 Caddy 路由均保持原状。

## SSH 运维凭据

- 103 使用本机专用密钥 `C:\Users\Administrator\.ssh\modelroute_103_ed25519`；私钥仅当前 Windows 用户可读写。
- 新 root 密码的受限本机副本位于 `C:\Users\Administrator\.ssh\modelroute_103_root_password.txt`，不得复制到仓库、文档正文、命令输出或工单。
- 轮换密码前必须先验证专用密钥登录；轮换后必须分别验证新密码成功、旧密码失效和密钥仍可登录。
- 删除服务器 `authorized_keys` 中的专用密钥前，必须先建立并验证另一条管理通道，避免失去服务器访问能力。
