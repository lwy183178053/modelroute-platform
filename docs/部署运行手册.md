# ModelRoute 部署运行手册

## 部署目录

生产目录固定为 `/opt/modelroute-platform`。运行数据位于该目录的 `data/`，备份位于 `backups/`，两者均排除在 Git 之外。

## 首次部署

1. 把发布归档解压到 `/opt/modelroute-platform`。
2. 创建权限为 `600` 的 `.env`，所有密码和密钥使用随机十六进制值。
3. 执行 `deploy/scripts/deploy.sh`。
4. 执行 `deploy/scripts/verify.sh http://127.0.0.1:28100`。
5. 备份 `/etc/caddy/Caddyfile`，追加 `deploy/caddy/aggregate.Caddyfile`。
6. 执行 `caddy validate --config /etc/caddy/Caddyfile`，验证通过后执行 `systemctl reload caddy`。
7. 执行 `deploy/scripts/verify.sh https://aggregate.lwylink.xyz`。
8. 设置 `ADMIN_PASSWORD_FILE` 后执行 `deploy/scripts/verify-accounts.sh https://aggregate.lwylink.xyz`，验证账号、管理员和临时密钥契约。
9. 执行 `deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz`，验证商户申请、权限、列表和密钥清除契约。

发布目录名必须使用对应 Git 提交的 12 位短哈希。部署脚本会解析 `current` 软链接的真实目录并把该目录名注入 `/api/version`，用于核对线上版本和回滚点。

宿主机已有 Caddy 负责公网证书。Caddy 自动签发的公有证书满足 Cloudflare Full Strict，不需要让 ModelRoute 容器接触证书私钥。

账号服务启用后，`.env` 还必须配置以下非密钥项：

```dotenv
PUBLIC_ORIGIN=https://aggregate.lwylink.xyz
SESSION_COOKIE_NAME=modelroute_session
SESSION_COOKIE_SECURE=true
SESSION_TTL=24h
NEW_API_REQUEST_TIMEOUT=30s
PLATFORM_ENCRYPTION_KEY=<Base64 编码的 32 字节随机密钥>
```

`PUBLIC_ORIGIN` 必须与浏览器实际来源完全一致。生产环境使用 HTTPS 时，`SESSION_COOKIE_SECURE` 保持为 `true`。

`PLATFORM_ENCRYPTION_KEY` 用于待审核商户渠道密钥的 AES-256-GCM 加密和 HMAC-SHA256 指纹。可使用 `openssl rand -base64 32` 生成；生产启用后必须与数据库备份一同受控保管，不得进入发布目录、Git 或终端记录。

## 邮件设置

注册验证码和密码重置邮件复用既有 SMTP 服务，但配置落点是 New API 原生系统设置，不是 ModelRoute `.env`：

1. 管理员登录 New API 内网管理接口。
2. 通过原生 `/api/option/` 接口设置 SMTP 主机、端口、账号、发件人、TLS 模式和密码，并启用邮箱验证。
3. 分别完成一次注册验证码和密码重置邮件实发测试。
4. 删除测试账号，确认没有测试用户残留。

SMTP 密码由 New API 设置数据库保存，因此 `newapi.dump` 属于敏感备份，必须放在受限目录中。终端输出、Git、平台接口和浏览器均不得出现密码正文。

## 生产验收

每次发布至少执行以下检查：

1. 在宿主机执行 `deploy/scripts/verify.sh http://127.0.0.1:28100`。
2. 执行 `deploy/scripts/verify.sh https://aggregate.lwylink.xyz`。
3. 设置 `ADMIN_PASSWORD_FILE` 后执行 `deploy/scripts/verify-accounts.sh https://aggregate.lwylink.xyz`。
4. 执行 `deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz`。
5. 确认 `/api/version` 与发布目录和 Git 提交一致。
6. 在服务稳定后的新时间窗口检查 Caddy 日志，避免把容器重启窗口内的 `context canceled` 误判为持续故障。
7. 确认 `api.lwylink.xyz` 和 `sdk.lwylink.xyz` 仍正常返回，且 New API、PostgreSQL、Redis 没有宿主机监听端口。

## 日常更新

1. 执行 `deploy/scripts/backup.sh`，保存两个 PostgreSQL 数据库的同一时间点备份。
2. 解压新版本并保留 `.env`、`data/` 和 `backups/`。
3. 执行 `deploy/scripts/deploy.sh`、基础验收和账号契约验收。
4. 验证未通过时恢复上一发布归档；数据库结构已变化时使用对应备份和 `restore.sh`。

## 数据恢复

恢复脚本会停止 API、Worker 和 New API，并清理目标数据库后导入备份。执行前必须设置 `CONFIRM_RESTORE=MODELROUTE_RESTORE`，且必须先保留当前数据库的新备份。

## 隔离要求

- Compose 项目名固定为 `modelroute`。
- 网关仅绑定 `127.0.0.1:28100`。
- New API、PostgreSQL 和 Redis 均不发布宿主机端口。
- Caddy 修改必须先备份、验证，再平滑 reload。
- Caddy 配置备份统一保存在 `/etc/caddy/backups/`。
- Sub2API 与 SDK 的容器、目录、数据库、端口和 Caddy 路由均保持原状。
