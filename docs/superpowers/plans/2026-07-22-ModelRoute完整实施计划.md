# ModelRoute API 聚合平台完整实施计划

## 目标

保留已确认的 React UI，自研统一官网、商户体系、路由、支付和管理后台；固定版本 New API 作为内网账号、渠道转发、缓存计费、余额和日志核心。

## 技术边界

- Go API 与后台任务、React 19 前端、PostgreSQL、Redis、Caddy/Nginx、Docker Compose。
- 公网只开放 `/`、`/api/*` 和首期三个 `/v1/*` 模型接口。
- `NEW_API_ADMIN_USERNAME` 唯一决定平台管理员身份，平台数据库决定商户身份；唯一管理员拥有真实官方商户资料并完全复用普通商户中心。
- 模型路由只把公开模型名替换成唯一报价别名，原始鉴权和请求继续交给 New API。
- 人民币支付购买美元额度，订单锁定汇率、人民币分、美元额度和 New API 整数额度。

## 实施阶段

1. 只读审计、Git 基线和私有远程仓库。
2. Go/React/Docker 部署底座、固定版本 New API、数据库迁移、HTTPS 和备份。
3. 注册登录、邮箱验证、服务端会话、三级权限和管理员用户管理。
4. 商户申请、审核、撤销、渠道凭据加密与 New API 渠道导入。
5. 官方价格、不可变报价、智能/固定路由、探活、冷却和流式透传。
6. 易支付设置、签名、异步回调、幂等订单和 New API 额度入账。
7. New API 日志同步、10%/90% 账本、退款冲正和人工提现。
8. 替代实际启用的 New API UI，完成压力、恢复、升级和上线验证。

## 验证原则

- 新业务代码采用测试先行，先观察目标测试失败，再实现最小代码使其通过。
- 每个阶段必须运行对应单元、集成、契约、UI 和部署检查。
- 每个阶段独立提交并创建回滚标签，验证证据追加到 `progress.md`。
