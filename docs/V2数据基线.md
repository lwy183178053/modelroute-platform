# ModelRoute V2 数据基线

## 适用范围

V2 迁移只用于全新空库。开发环境发布时先备份 103 的平台库、New API 库和受限配置，完成临时恢复演练后再显式执行重置；101、102 不在操作范围内。

## 核心关系

- 一条商户渠道只绑定一个标准模型，渠道保存自动检测得到的内部适配器，不保存用户选择的渠道类型。
- 商户提交渠道前必须获得 15 分钟有效的检测凭证；检测记录绑定用户、标准模型、基础地址和密钥指纹。
- 报价按“商户 + 标准模型”唯一激活，同一报价版本为该商户的每条同模型渠道生成独立内部别名。
- 商户倍率使用整数基点，范围为 `0..50000`；`0` 与其他倍率走同一计费表达式。
- 标准模型只支持 Chat Completions、Responses 和 Image Generation。
- 文本价格使用连续上下文阶梯；图片价格使用“质量 + 尺寸 + 单张价格”矩阵。

## 健康与支付

- 健康状态下 `next_probe_at` 为空，只有冷却或恢复中的渠道才进入探活队列。
- 人民币支付只保存人民币分和 New API 整数额度，固定换算为 `1 元 = 500000` 额度。
- 账本继续以 New API 整数额度记账，展示层按固定换算显示人民币。

## 回滚边界

V2 不包含旧迁移的升级兼容分支。代码回滚使用阶段提交；103 一旦执行重置，数据回滚必须同时恢复同一时间点的平台库、New API 库、Redis 和受限配置备份。

生产重置只通过 `deploy/scripts/reset-v2-data.sh` 执行。脚本要求 `CONFIRM_V2_RESET=MODELROUTE_V2_RESET_103`，同时校验 103 地址、Git 哈希发布目录、共享数据真实路径和 Compose 项目名；它会先创建完整备份并完成临时数据库恢复演练，再清理四个固定的 ModelRoute 数据子目录。脚本不接受其他项目路径参数。
