# 多模型渠道与运营界面升级

## 渠道流程

商户在渠道弹窗选择 `OpenAI 兼容`、`Anthropic` 或 `Gemini`，填写一个上游地址和密钥后点击“一键同步模型”。平台通过 New API 原生渠道模型接口读取上游模型，并按规范化模型名称匹配管理员模型目录。OpenAI 兼容和 Anthropic 地址末尾的 `/v1`、Gemini 地址末尾的 `/v1beta` 会在传给 New API 时去除，平台仍保留商户提交的基础地址。已匹配模型可进入报价，未匹配模型只显示“平台未收录”。

提交审核时服务端会重新同步一次，不信任浏览器提交的模型清单。审核期间密钥以加密正文保存，审核结束清除正文，只保留密钥指纹和模型绑定记录。管理员先验证审核记录，再按需要对某个已匹配模型发送 `hi` 检查；检查结果记录在审核模型表中，最终是否通过仍由管理员决定。通过后创建一个包含全部匹配模型的 New API 渠道。

已导入渠道支持再次同步模型、启用/下架和删除。删除在平台侧执行归档，避免历史报价、结算和审计记录失去关联。

## 接口

- `POST /api/merchant/channel-models/sync`：临时同步上游模型并返回匹配结果。
- `POST /api/merchant/channels`：服务端重新同步并创建多模型审核记录。
- `POST /api/merchant/channels/{id}/models/sync`：通过 New API 渠道编号刷新已导入渠道模型。
- `POST /api/admin/channel-reviews/{id}/model-tests`：管理员按审核模型绑定编号执行 `hi` 检查。
- `POST /api/merchant/channels/{id}/status`、`DELETE /api/merchant/channels/{id}`：商户管理自己的渠道。
- `POST /api/admin/channels/{id}/status`、`DELETE /api/admin/channels/{id}`：管理员停用或归档任意渠道。
- `GET /api/admin/channel-logs`：沿用 New API 日志查询，支持 `username` 和 `channel` 筛选。
- `GET /v1/models`：保留 OpenAI 兼容模型列表代理，并清理内部报价别名。

## 数据边界

`merchant_review_model_bindings` 保存审核期间的逐模型匹配和检查结果；审批完成后复制到 `merchant_channel_model_bindings`。旧的 `canonical_model_id` 字段保留第一个匹配模型，供旧接口和历史数据兼容。报价和路由查询同时检查多模型绑定表，因此同一渠道可以为多个标准模型生成报价别名。

MiniMax 不在新的厂商白名单、模型种子、图标、筛选和渠道类型中。历史 MiniMax 模型由迁移归档并停止报价，开发库重置时不重新导入。
