# ModelRoute 绝对价格与分层计费

## 业务口径

管理员按每百万 Token 录入官方绝对价格。商户只设置 `1..10000` 基点的折扣，`10000` 表示官方原价，任何报价都不得高于官方价格。

模型原币支持美元和人民币。每个官方价格版本独立锁定核价汇率、核价来源和核价时间；充值人民币兑美元汇率与模型核价完全分离。

## 整数换算

所有账务计算均使用整数：

```text
美元微价 = 四舍五入(原币微价 × 每原币美元汇率微值 ÷ 1,000,000)
商户美元微价 = 四舍五入(美元微价 × 商户折扣基点 ÷ 10,000)
```

输入价格和非 Embeddings 输出价格折后低于 `1` 微美元时拒绝上架。缓存价格为可选项；未单独配置的缓存 Token 由 New API 归入输入 Token 计价。

## 价格阶梯

- 第一档从 `0` Token 开始。
- 非末档必须设置包含式上限，下一档起点必须等于上一档上限加 `1`。
- 最后一档不设置上限。
- 每档可保存输入、输出、缓存读取、5 分钟缓存写入和 1 小时缓存写入价格。
- Embeddings 只接受输入价格；Chat Completions 和 Responses 必须同时提供输入与输出价格。

## 管理界面

- 模型厂商固定为 OpenAI、Anthropic、Gemini、DeepSeek、Qwen、Moonshot 和 Minimax，并显示对应厂商图标。
- 协议固定为 Chat Completions、Responses 和 Embeddings；生命周期固定为稳定版、Preview、限量和临近退役。
- 新建模型和发布价格都直接录入原币、独立核价汇率、核价来源、核价时间和每百万 Token 单价，不再显示倍率或固定计费选项。
- 新增价格阶梯时，界面自动从上一档上限加一生成下一档起点；最后一档始终显示为无上限。
- 模型市场和商户报价页同时显示官方价折扣及折后输入、输出美元单价，多档价格额外标注上下文阶梯数量。

## New API 适配

平台为每个商户报价生成不可变表达式，并同步到 New API：

```text
billing_setting.billing_mode = {"内部别名":"tiered_expr"}
billing_setting.billing_expr = {"内部别名":"v1:..."}
```

表达式使用 New API `rc.21` 的原生变量：`len` 判断上下文档位，`p`、`c`、`cr`、`cc`、`cc1h` 分别计算输入、输出、缓存读取、5 分钟缓存写入和 1 小时缓存写入。

平台在同步前使用与 New API 相同版本的 `expr-lang` 编译并执行四组金额向量。两项价格配置和渠道模型映射全部成功后才激活报价；任一步失败时新版本保持 `sync_failed`，旧报价继续服务。

## 数据升级

`000008_absolute_pricing.sql` 增加模型生命周期、价格版本元数据和 `price_tiers`：

- 历史 Token 倍率按 New API 的美元口径换算为单档美元绝对价格。
- 历史固定计费版本保留为 `legacy_fixed`，对应模型设为停用。
- 旧倍率字段继续保留，只作为数据库回滚兼容数据；新请求和新报价不再读取这些字段。

生产执行第 8 号迁移前必须同时备份平台库和 New API 库。已经同步新表达式后若跨版本回退，必须恢复同一时间点的两份数据库备份。
