# ModelRoute 模型报价、路由与渠道健康

## 业务边界

ModelRoute 只在请求进入 New API 前完成候选选择，并把公开模型名替换为唯一内部报价别名。New API 继续负责 API 密钥鉴权、上游模型转发、缓存命中计费、预扣、退款、余额和最终消费日志。

平台不解析 Token 数量，不重新计算缓存费用，也不保存提示词或模型返回正文。路由记录只保留请求编号、模型、渠道、报价版本、状态码和首字节耗时。

## 标准模型与官方价格

管理员通过 `/api/admin/models` 建立标准模型，首期协议只允许：

- `chat_completions`：对应 `/v1/chat/completions`。
- `responses`：对应 `/v1/responses`。
- `embeddings`：对应 `/v1/embeddings`。

官方价格每次发布都生成新版本。新模型只接受每百万 Token 绝对价格，不再录入 New API 倍率或固定单次价格：

- 原币支持美元和人民币，所有价格使用原币微单位保存。
- 每个价格版本锁定“每原币可兑换多少美元”的整数微汇率，充值汇率不参与模型核价。
- 每档保存输入、输出、缓存读取、5 分钟缓存写入和 1 小时缓存写入价格。
- 阶梯从 `0` Token 开始连续衔接，最后一档无上限；Embeddings 只保存输入价格。
- 模型生命周期分为稳定版、Preview、限量和临近退役，只有稳定版新建后默认启用。

旧 Token 倍率在第 8 号迁移中换算为单档美元绝对价格；旧固定计费记录保留作回滚依据并停用，不进入新目录。新官方价格发布后，基于旧官方价格的报价退出新请求路由，但旧报价别名仍保留，供在途请求、日志同步和退款追溯。

## 商户报价

商户只能选择已审核并处于正常状态的自有渠道，以及管理员已发布的标准模型。商户在界面录入官方价折扣，服务端仍使用整数基点保存：

```text
1 基点 = 0.0001x
10000 基点 = 1.0000x
```

商户中心对普通商户和唯一管理员使用同一个页面组件、同一组商户接口和同一套权限判断。工作区固定为经营概览、渠道管理、模型报价、健康状态、结算账本和提现记录六个侧栏入口；管理员只在官网主导航额外看到管理后台，不增加管理员专用商户操作。

报价同步顺序如下：

1. 平台数据库创建 `syncing` 报价版本和随机内部别名。
2. 读取 New API 当前价格设置，保留已有模型价格。
3. 先按锁定汇率把原币微价换算为美元微价，再按整数基点计算商户折后价格；每一步均执行整数四舍五入。
4. 把内部别名加入目标 New API 渠道，并建立“内部别名到公开模型”的映射。
5. 所有同步成功后激活新报价，再退役同渠道、同模型的旧报价。

每个内部别名统一写入 New API 的 `billing_setting.billing_mode=tiered_expr` 与不可变 `billing_setting.billing_expr`。表达式使用 `len` 判断阶梯，使用 `p/c/cr/cc/cc1h` 计算输入、输出、缓存读取、5 分钟写入和 1 小时写入费用。

同步中任何一步失败，新报价进入 `sync_failed`，旧报价继续服务。市场和商户接口返回折扣基点及折后各档美元价格，内部别名不会通过市场、商户或管理员接口返回给浏览器。

## 用户路由策略

每个 New API 密钥在平台保存一条独立策略。平台只保存密钥的 HMAC-SHA256 指纹，不保存密钥正文。

默认策略为：

- 模式：智能路由。
- 优先级：稳定性优先。
- 倍率区间：`1..10000` 基点。
- 商户范围：全部符合条件的商户。

策略模式：

- 智能路由：在倍率区间、渠道状态和健康状态均合格的全部报价中选择。
- 固定商户：只在用户选定的商户中选择；固定名单为空时拒绝保存。

排序规则：

- 价格优先：先按倍率升序，再按健康、可用率和 P95 首字时间排序。
- 稳定性优先：先按健康、可用率和 P95 首字时间排序，再比较倍率。

无候选时返回 OpenAI 兼容 `503`，错误码为 `no_available_channel`。请求尚未向客户端写出首字节时，候选返回 `429` 或 `5xx` 可切换下一候选；首字节写出后停止换路。

## 请求处理

`/v1/*` 请求流程：

1. 校验 Bearer 密钥格式并计算指纹。
2. 从 JSON 正文读取公开 `model`，不修改其他字段。
3. 按密钥策略查询候选并记录路由决策。
4. 仅把 `model` 替换为选中报价的内部别名。
5. 原始 Authorization 和请求头继续交给 New API。
6. New API 响应状态、响应头和流式正文直接返回客户端。
7. 平台记录结果元数据，最终扣费仍以 New API 日志为准。

单次请求正文上限为 64 MiB。模型协议与访问路径不匹配时返回 `400/unsupported_model_protocol`。

## 探活、冷却与恢复

Worker 每 10 秒领取到期探活任务，使用 New API 服务账号持有的专用不限额令牌请求内部报价别名。令牌编号写入 `platform_runtime_metadata.newapi_probe_token_id`，后续结算同步必须排除该令牌。

健康状态：

- `pending`：等待首次探测。
- `healthy`：可参与路由。
- `degraded`：出现临时故障但尚未达到冷却阈值。
- `cooling`：连续三次临时故障后暂时退出路由。
- `recovering`：冷却结束后的恢复探测阶段。
- `disabled`：硬故障，平台渠道和 New API 渠道均停用。

临时故障包括 `429` 和 `5xx`，冷却阶梯为 `1、5、15、30、60` 分钟。有效 `Retry-After` 大于当前档位时采用其时长。冷却结束后必须连续两次、间隔至少 10 秒探测成功才恢复健康。连续健康 24 小时后冷却等级重置。

主动探活遇到 `401`、`402` 或 `403` 视为硬故障。管理员恢复渠道时先启用 New API 渠道，再把平台健康状态重置为 `pending`；若平台重置失败，会补偿停用 New API 渠道。

真实请求同样累计成功率、首字节耗时和临时故障次数。连续三次临时故障会进入一分钟冷却，之后由主动探活完成恢复判断。

## 接口

公开只读：

- `GET /api/models`
- `GET /api/offers`

普通用户：

- `GET /api/routing-policies/{token_id}`
- `PUT /api/routing-policies/{token_id}`

商户：

- `GET /api/merchant/offers`
- `POST /api/merchant/offers`
- `GET /api/merchant/health`

管理员：

- `GET /api/admin/models`
- `POST /api/admin/models`
- `POST /api/admin/models/{id}/prices`
- `POST /api/admin/channels/{id}/health/reset`

模型调用：

- `POST /v1/chat/completions`
- `POST /v1/responses`
- `POST /v1/embeddings`

所有平台写接口同时校验有效会话、账号状态、角色和同源请求。`/v1/*` 保持 OpenAI 兼容错误结构，不使用平台业务信封。

## 配置与验收

API 和 Worker 都需要 New API 服务账号：

```dotenv
NEW_API_ADMIN_USERNAME=modelroute
NEW_API_ADMIN_PASSWORD=<受限管理员密码>
```

密码只保存在服务器权限为 `600` 的共享 `.env`，不得写入发布目录、Git、文档或命令输出。

本地验证：

```bash
cd apps/api
go test ./...
go vet ./...
go build ./cmd/...

cd ../web
npm run test:ui
npm run capture

cd ../..
python -m unittest discover -s deploy/tests -p 'test_*.py'
docker compose --env-file .env.example config --quiet
```

真实 PostgreSQL 测试设置临时数据库后执行：

```bash
MODELROUTE_TEST_DATABASE_URL='postgres://USER:PASSWORD@HOST:PORT/platform?sslmode=disable' \
  go test ./internal/httpapi -run TestSQLRoutingStoreAgainstPostgres -count=1 -v
```

生产部署后执行：

```bash
deploy/scripts/verify-routing.sh https://aggregate.lwylink.xyz
```

## 回滚

第 3 份迁移只新增表、外键和索引，不修改 New API 数据库。应用回滚时先把 `current` 切换到上一发布目录并重新部署；由于旧版本不了解新增路由表，表可以暂时保留。

需要连数据库结构一起回退时，使用本阶段发布前的平台库备份和 `restore.sh`。报价已经同步到 New API 后，数据库恢复与 New API 设置必须使用同一发布前时间点，避免别名、渠道映射和价格配置不一致。
