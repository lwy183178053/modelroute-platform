# ModelRoute 账号与管理员接口

## 职责边界

- New API 保存账号、密码、角色、状态、额度、API 密钥和最终用量。
- ModelRoute 不直接修改 New API 用户表，只通过固定版本的原生接口完成读写。
- 浏览器只持有 ModelRoute 随机会话 Cookie；New API 会话仅保存在 Redis。
- 浏览器响应不返回上游 Cookie、管理凭据或内部商户资料编号。

## 账号和权限

| New API 角色 | 平台身份 | 页面权限 |
| --- | --- | --- |
| `1` | 普通用户 | 模型市场、控制台 |
| `10`、`100` 且用户名等于 `NEW_API_ADMIN_USERNAME` | 唯一管理员 | 普通用户页面、普通商户中心、管理后台 |

平台全局只承认 `NEW_API_ADMIN_USERNAME` 指定的一个管理员账号。其他账号即使在 New API 中带有 `10` 或 `100` 角色，进入 ModelRoute 后也按普通用户处理。管理员拥有一条真实的“ModelRoute 官方”商户资料，使用与普通商户完全相同的商户页面、接口和操作，只额外显示管理后台。前端导航只负责展示，所有平台接口仍在服务端校验账号状态和最低角色。

普通商户和唯一管理员进入商户中心后均使用经营概览、渠道管理、模型报价、健康状态、结算账本和提现记录六个入口。两种账号不按角色分支渲染商户功能，渠道、报价、健康、账本和提现由服务端根据登录用户解析归属；`/api/me` 只返回用户 ID、账号类型和商户状态，不返回内部商户资料编号。

用户控制台的“账户设置”采用双栏资料布局：左侧显示头像、用户 ID、当前工作区和对应入口，右侧按独立行显示登录账号、邮箱和用户类型；移动端自动上下排列，账号资料保持独立行高，不与身份摘要或工作区操作混排。申请商户审核中的提示和驳回原因固定显示在账号资料下方。

所有列表的“操作”列统一使用三点折叠菜单。菜单打开后显示当前行可用动作，危险动作使用红色标识；点击菜单外部、按 `Esc` 或改变窗口尺寸会关闭菜单。操作菜单采用固定定位，表格横向滚动时不会被裁切，移动端也保持单行高度。

## 会话流程

1. 登录请求由 ModelRoute 转发到 New API。
2. New API 的 `session` Cookie 写入 Redis，不返回浏览器。
3. 浏览器收到 `HttpOnly + Secure + SameSite=Strict` 的平台 Cookie。
4. `/api/me` 每次向 New API 刷新角色、状态和额度，并再次按唯一管理员用户名归一化角色；账号被封禁或上游会话失效时清理平台会话。
5. 封禁用户或由管理员重置密码后，清理该用户的全部平台会话。

客户端来源 IP 经网关校验后传给 New API，供其登录审计和 IP 限流使用。

## 已开放接口

### 登录和账号

- `POST /api/auth/login`
- `POST /api/auth/login/2fa`
- `POST /api/auth/register`
- `POST /api/auth/email-verification`
- `POST /api/auth/password-reset/request`
- `POST /api/auth/password-reset/confirm`
- `POST /api/auth/logout`
- `GET /api/me`

密码重置确认成功后，New API 直接生成并返回新密码。页面只在当前重置弹窗展示一次，用户可立即复制。

### API 密钥

- `GET /api/keys`
- `POST /api/keys`
- `PUT /api/keys/{id}`
- `POST /api/keys/{id}/status`
- `DELETE /api/keys/{id}`

密钥列表返回当前账号可复制的密钥；控制台不再提供单独的“查看”接口或按钮。密钥不写入平台数据库。

账号余额按人民币显示：`500000` New API 整数额度等于 `¥1`。后台额度调整接口仍接收 New API 整数额度，避免账务换算使用浮点数。

### 管理员

- `GET /api/admin/users`
- `GET /api/admin/users/{id}`
- `POST /api/admin/users/{id}/status`
- `POST /api/admin/users/{id}/quota`
- `POST /api/admin/users/{id}/password`
- `POST /api/admin/users/{id}/merchant-status`

用户列表支持按 `user`、`merchant`、`admin` 类型筛选。商户身份的撤销与恢复并入用户管理，不再维护独立商户权限列表。额度调整支持增加、扣减和覆盖三种模式，数值使用 New API 整数额度。管理员重置密码时会保留目标用户的账号、显示名称、分组和备注。

## 运行配置

- `PUBLIC_ORIGIN`：浏览器公开来源，用于写操作来源校验。
- `SESSION_COOKIE_NAME`：平台会话 Cookie 名称。
- `SESSION_COOKIE_SECURE`：生产环境必须为 `true`。
- `SESSION_TTL`：平台会话有效期。
- `NEW_API_REQUEST_TIMEOUT`：账号类 New API 请求超时。
- `NEW_API_ADMIN_USERNAME`：ModelRoute 唯一管理员用户名，同时也是管理员直属官方商户的归属账号。

上述变量只包含账号服务配置。平台数据库密码和后续支付密钥保存在服务器受限环境文件中；SMTP 配置通过 New API 原生管理接口写入其设置数据库，不写入平台 `.env`。New API 数据库备份按敏感文件管理，SMTP 密码不得进入 Git、平台接口或浏览器。

## 本地 V2 验收

- 管理员登录、类型化用户列表、密钥创建、复制、启停、删除和退出均由本地契约覆盖。
- 已删除的密钥查看、操作记录和系统任务路由由服务端测试确认不再注册。
- 封禁、解封、额度调整、密码重置和商户身份变更均通过平台接口执行，平台不直接修改核心用户表。
