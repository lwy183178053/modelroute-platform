# ModelRoute 商户与渠道审核接口

## 业务边界

- New API 继续负责账号、角色、余额、密钥、模型转发和原生计费。
- 平台数据库单独记录商户申请、有效商户身份、渠道审核版本和 New API 渠道归属。
- 普通用户、商户和管理员共用 New API 账号；有效商户身份必须由平台数据库再次确认，不能只依赖前端导航或 New API 角色。
- 管理员继承普通用户和商户页面访问能力，但全部管理员接口仍要求 New API 管理员角色。

## 申请与审核状态

商户申请和初始渠道审核共用以下状态：

1. `pending`：等待管理员处理，凭据为 AES-256-GCM 密文。
2. `verifying`：管理员已原子认领验证任务。
3. `verified`：New API 已读取上游模型列表，拟售模型全部存在，等待批准。
4. `approving`：正在创建并测试 New API 渠道。
5. `approved`：渠道归属已落库，待审核密钥密文已清除。
6. `rejected`：申请已驳回，待审核密钥密文已清除。

同一用户同时只允许一条进行中的商户申请。已有 `active` 商户不能重复提交商户申请；被撤销的商户可重新申请。新增渠道使用独立审核记录，不覆盖旧审核历史。

## 密钥生命周期

- 浏览器提交上游密钥后，平台使用 `PLATFORM_ENCRYPTION_KEY` 加密，并使用 HMAC-SHA256 生成不可逆指纹。
- API 响应只返回 `credential_configured`，不返回密钥、密文或完整指纹。
- 管理员验证和批准时仅在服务内存中短暂解密，调用结束后覆盖明文字节。
- 批准或驳回后数据库约束要求密文字段为空；已导入渠道只保留缩短后的指纹和 New API 渠道编号。
- New API 管理会话、商户密钥和平台加密主密钥均不进入浏览器、Git、日志或中文文档。

## New API 导入流程

1. 调用 New API `/api/channel/fetch_models` 验证基础地址、密钥和可用模型。
2. 以唯一名称 `ModelRoute-R<审核编号>-U<用户编号>` 创建 New API 渠道。
3. 通过 New API 渠道搜索接口取得新渠道编号。
4. 使用首个拟售模型执行 New API 原生渠道测试。
5. 测试成功后，在同一平台数据库事务中创建或恢复商户资料、写入渠道归属、更新申请状态并清除密文。
6. 测试失败或平台事务失败时删除刚创建的 New API 渠道，并把审核恢复到可重试状态。

New API 源码和数据库表保持原样；平台只调用其原生管理接口。

## 用户接口

- `GET /api/merchant/application`：读取当前账号最近一条商户申请。
- `POST /api/merchant/application`：提交商户资料和初始渠道。
- `GET /api/merchant/channels`：有效商户读取自身渠道、审核版本和商户身份。
- `POST /api/merchant/channels`：有效商户提交新渠道审核。

所有写接口要求平台会话、有效账号状态和同源请求。商户接口还会在服务端检查平台商户身份与状态。

## 管理员接口

- `GET /api/admin/merchant-applications`
- `GET /api/admin/merchant-applications/{id}`
- `POST /api/admin/merchant-applications/{id}/verify`
- `POST /api/admin/merchant-applications/{id}/approve`
- `POST /api/admin/merchant-applications/{id}/reject`
- `GET /api/admin/merchants`
- `POST /api/admin/merchants/{id}/status`
- `GET /api/admin/channel-reviews`
- `POST /api/admin/channel-reviews/{id}/verify`
- `POST /api/admin/channel-reviews/{id}/approve`
- `POST /api/admin/channel-reviews/{id}/reject`
- `GET /api/admin/channels`

验证、批准、驳回、撤销和恢复均写入平台审计日志。撤销商户权限前先停用该商户的 New API 渠道；平台状态事务失败时尝试恢复已变更的 New API 渠道。

## 运行配置

生产环境必须设置：

```dotenv
PLATFORM_ENCRYPTION_KEY=<Base64 编码的 32 字节随机密钥>
```

可使用 `openssl rand -base64 32` 生成。该密钥一旦投入使用必须随数据库备份一起受控保管；丢失后，仍处于待审核状态的上游密钥将不能解密。

## 验证

本地验证：

```powershell
cd apps/api
go test ./...
go vet ./...
go build ./cmd/...

cd ../web
npm.cmd run test:ui
npm.cmd run capture
```

生产部署后执行：

```sh
deploy/scripts/verify-merchants.sh https://aggregate.lwylink.xyz
```

线上契约脚本验证匿名权限、管理员登录、申请创建、列表读取、密钥不回显、驳回和密文清除。脚本使用随机测试凭据，并保留已驳回记录作为审计证据，不触发真实上游验证或渠道导入。
