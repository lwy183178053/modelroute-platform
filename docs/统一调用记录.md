# ModelRoute 统一调用记录

## 业务口径

- 用户、商户和管理员共用 `settlement_sources` 消费事实表，不再复制三份调用日志。
- 产品只展示 `source_type = 2` 且 `status = settled` 的成功消费；失败请求不计商户收入。
- 调用明细默认不限制时间范围，永久保留并通过服务端分页读取；账户概览的最近 7 天只用于趋势图。
- 分页固定支持每页 `20`、`50` 或 `200` 条，提供首页、上一页、下一页和尾页。
- 成功消费完成后按整数额度自动拆分：商户获得 90%，平台获得 10%。平台不提供单次退款、人工结算或人工对账入口；管理员补回用户额度属于独立的余额调整。

## 共用字段

每条记录保存消费日志 ID、时间、消费用户 ID、模型、API 密钥 ID、输入 Token、输出 Token、缓存 Token、消费额度、商户收入、商户用户 ID、商户名称、平台渠道 ID、渠道名称和请求编号。

提示词、模型回复、上游密钥、内部模型别名和内部渠道编号不进入浏览器响应。

## 查询视角

- `GET /api/usage`：只查询当前用户，可按模型和商户用户 ID 筛选；同时返回最近 7 天趋势数据。
- `GET /api/merchant/usage`：只查询当前登录商户，可按模型筛选；请求参数不能覆盖当前商户范围。
- `GET /api/admin/channel-logs`：管理员可按商户用户 ID、平台渠道 ID 和模型筛选全平台成功消费。

用户页面显示商户名称和商户用户 ID；商户页面显示承载渠道和自动入账金额，不显示消费用户身份；管理员页面显示消费用户、商户和渠道，用于运营核查。

## 内部记账

消费事实同步、幂等分账、核心服务失败冲正、商户余额和提现账本继续保留在服务内部，不作为独立产品页面开放。核心服务对失败调用自动退回用户额度；已成功完成的调用不提供逐条退款操作。

## 验证

Go 测试覆盖用户、商户和管理员范围隔离，成功消费过滤、模型与商户筛选、渠道筛选、无默认保留窗口、分页边界、商户 90% 收入以及商户参数越权。前端烟雾测试覆盖三种视角的筛选、字段、分页和移动端布局。
