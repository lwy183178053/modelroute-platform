# 易支付人民币充值

## 业务边界

- 用户直接选择人民币充值金额，`¥1` 对应核心页面余额 `1.00`。
- New API 是用户余额的唯一权威来源；平台只在支付成功后调用其原生管理员额度接口。
- 浏览器支付返回页只查询订单，入账只由验签通过的异步通知触发。
- 支付配置、订单、回调事件和入账操作保存在平台 PostgreSQL；完整 KEY 使用 AES-256-GCM 加密且永不回显。

## 整数口径

- 人民币金额保存为 `amount_cny_cents`，例如 `¥100.00` 保存为 `10000`。
- 核心原始额度保存为 `newapi_quota`，换算公式为 `amount_cny_cents * quota_per_unit / 100`。
- `quota_per_unit` 在平台启动时从核心 `/api/status` 读取；该值必须是可精确表示人民币分的正整数，否则平台停止启动，避免错账。
- 最低和最高充值金额均使用人民币分。
- 数据库和 Go 业务代码不使用浮点账务；前端输入会由服务端重新解析和计算。

## 配置与订单

管理员在“支付与充值”维护网关地址、PID、KEY、支付方式、人民币充值范围、提现税率和启用状态。提现税率允许设置为 `0.00%..100.00%`，最多两位小数，接口使用整数基点 `withdrawal_tax_bps` 保存，其中 `100` 表示 `1.00%`。

每次保存创建不可变配置版本；编辑时 PID 和 KEY 可留空沿用。充值订单只锁定配置版本、人民币金额和按当前核心单位换算出的原始额度，不包含美元金额或汇率。商户提交提现时会把当前配置版本中的税率复制到提现申请，管理员后续调整税率只影响新申请。

易支付签名按参数名 ASCII 排序，排除 `sign`、`sign_type` 和空值，拼接后直接追加 KEY 并计算小写 MD5。回调必须同时通过签名、PID、平台订单号、第三方交易号、人民币金额、支付方式和 `TRADE_SUCCESS` 校验。

## 幂等与异常处置

- 支付回调以回调键、第三方交易号和订单行锁防止重复认账。
- 每个订单只有一条 New API 入账操作和一个幂等键。
- 明确失败最多自动尝试 5 次；网络中断等结果不确定时进入 `unknown`，停止自动重试。
- 管理员核对 New API 余额和审计后，可确认已入账或确认未入账后重新排队。

## 接口

用户接口：

- `GET /api/payment-settings`
- `POST /api/payment-orders`
- `GET /api/payment-orders`
- `GET /api/payment-orders/{order_no}`

管理员接口：

- `GET /api/admin/payment-settings`
- `PUT /api/admin/payment-settings`
- `GET /api/admin/payment-orders`
- `POST /api/admin/payment-orders/{id}/credit/retry`
- `POST /api/admin/payment-orders/{id}/credit/resolve`

网关入口：

- `GET|POST /api/payments/easypay/notify`
- `/payments/return`

## 验证与回滚

本地 Go 测试覆盖金额解析、整数换算、签名、金额篡改、重复及并发回调、入账失败和结果未知处置。生产只读验收使用：

```sh
deploy/scripts/verify-payments.sh https://aggregate.lwylink.xyz
```

回滚支付结构时先停止 API 和 Worker，再恢复同一发布前平台数据库备份；支付 KEY 只保存在服务器受限配置和加密数据库中。
