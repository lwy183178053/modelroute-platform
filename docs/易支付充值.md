# 易支付充值

## 业务边界

- 用户选择美元额度，订单按当时的人民币兑美元汇率计算人民币应付金额。
- New API 仍是用户余额的唯一权威来源；平台只在支付成功后调用 New API 原生管理员额度接口。
- 浏览器支付返回页只查询订单，不创建入账任务，也不改变支付或余额状态。
- 异步通知支持易支付常见的 GET 和 POST 形式，只有签名、PID、订单号、人民币金额、支付方式和 `TRADE_SUCCESS` 全部一致才认账。
- 支付配置、订单、回调事件和入账操作均在平台 PostgreSQL 中保存；完整支付 KEY 使用平台 AES-256-GCM 密钥加密，接口只返回配置状态和 PID 掩码。

## 整数口径

- 用户输入转换为 `usd_cents`，例如 `$100.00` 保存为 `10000`。
- 汇率保存为 `exchange_rate_cny_cents_per_usd`，例如 `¥7.20 / $1` 保存为 `720`。
- 人民币实付保存为 `cny_cents`，使用整数四舍五入：`(usd_cents * rate + 50) / 100`。
- New API 额度保存为 `newapi_quota`，换算规则为 `usd_cents * 5000`。
- 数据库和 Go 业务代码不使用浮点账务；前端小数只用于输入与展示，服务端重新计算并锁定权威值。

## 配置版本与订单

管理员在“支付与充值”页面维护：

- 易支付网关地址。
- 商户编号 PID。
- 商户密钥 KEY。
- 启用状态和支付方式。
- 最低、最高美元充值额度。
- 人民币兑美元汇率。

每次保存都会创建新的不可变配置版本。编辑已有配置时 PID 和 KEY 可留空沿用；完整 KEY 保存后不再回显。订单记录配置版本、汇率、美元额度、人民币金额和 New API 整数额度，因此后续调汇率不会改变旧订单。

## 两层幂等与入账状态

第一层是支付回调：

- `callback_key` 唯一。
- 第三方交易号唯一。
- 同一平台订单使用行锁串行认账。
- 相同订单和相同第三方交易号重复通知直接返回纯文本 `success`。
- 同一订单出现不同第三方交易号时进入冲突，不重复创建入账操作。

第二层是 New API 入账操作：

- 每个支付订单只有一个 `idempotency_key` 和一条入账操作。
- Worker 使用 `FOR UPDATE SKIP LOCKED` 领取，领取前把操作和订单写为 `processing`。
- New API 返回明确 API 错误时写为 `failed`，最多自动尝试 5 次，管理员也可重新排队。
- 网络超时、连接中断等不能确定 New API 是否已经加款的情况写为 `unknown`，自动任务停止重试。
- `processing` 超过 5 分钟仍未完成时转为 `unknown`，覆盖调用成功后进程中断的情况。

## 结果未知的人工核对

管理员必须先核对 New API 用户余额和管理员操作审计，再选择：

1. **确认已入账**：把平台操作和订单标为成功，不再次调用 New API。
2. **核对后重试**：确认此前没有加款后重新排队，下一轮 Worker 才会再次调用 New API。

两种操作都要求填写原因并写入平台审计日志。普通“重试入账”按钮只处理 `failed`，不接受 `unknown`。

## 接口

用户接口：

- `GET /api/payment-settings`：读取启用状态、支付方式、美元额度范围和汇率。
- `POST /api/payment-orders`：创建锁定金额的充值订单并返回服务端签名支付地址。
- `GET /api/payment-orders`：读取自己的订单。
- `GET /api/payment-orders/{order_no}`：按当前用户读取订单详情。

管理员接口：

- `GET /api/admin/payment-settings`：读取脱敏配置。
- `PUT /api/admin/payment-settings`：发布新配置版本。
- `GET /api/admin/payment-orders`：读取全站充值和入账状态。
- `POST /api/admin/payment-orders/{id}/credit/retry`：重新排队明确失败的入账。
- `POST /api/admin/payment-orders/{id}/credit/resolve`：人工处置结果未知的入账。

网关入口：

- `GET|POST /api/payments/easypay/notify`：异步通知；成功固定返回 `success`。
- `/payments/return`：浏览器支付返回页，只调用订单详情 GET。

```sh

```

契约脚本不创建真实订单、不读取支付 KEY，只验证权限、返回页和无效回调拦截。

## 回滚

- 代码回滚使用第 5 阶段标签 `phase-5-routing` 或第 6 阶段发布前提交。
- 数据库新增第 4 份迁移；需要连数据库回退时，先停止 API 和 Worker，再使用发布前平台库备份恢复。
- 回滚代码但保留第 4 份表结构不会让旧版本使用支付表，仍建议生产回滚按同一发布备份恢复，避免版本证据不一致。
