# 运营管理与升级验收

## 业务范围

ModelRoute 自研页面覆盖当前启用的账号、商户、渠道、模型、支付与结算功能，核心服务页面和管理端口保持内网状态。核心服务继续负责账号、密钥、余额、模型转发、缓存计费和最终消费日志，平台只通过内部接口读写，不直接修改核心用户表。

## 用户功能

- 控制台从 `/api/usage` 读取最近 7 天用量趋势、结算额度、RPM、TPM、缓存 Token 和调用日志，单次查询最多 31 天。
- 用量响应会把内部报价别名映射回标准模型名；映射缺失时统一显示“平台路由模型”，不会向浏览器返回 `mkt-ov-*`。
- 用户通过 `/api/redemptions/redeem` 使用 New API 原生兑换码充值；成功后重新读取 `/api/me`，余额继续以 New API 整数额度为准。

## 管理员功能

- `/api/admin/overview` 使用平台结算账本、路由决策、审核队列、渠道健康和同步水位生成真实运营总览，金额均为整数额度。
- `/api/admin/overview` 展示全平台成交、请求、商户应计、平台收入、退款和渠道状态。
- `/api/admin/channel-logs` 读取最终消费日志，支持按商户用户 ID 和平台渠道 ID 筛选；内部渠道编号不返回页面。
- `/api/admin/platform-settings` 管理 SMTP 与注册登录开关。SMTP 密码只写不读；空密码表示保留现有密码，接口不返回密码正文。
- 外围不提供分组倍率页面或接口；全部账号统一使用 New API 内部隐藏的 `default=1x` 分组。
- `/api/admin/redemptions` 覆盖兑换码创建、编辑、启停、删除和失效清理，额度始终使用 New API 整数额度。
- 渠道审核记录与已审核渠道合并为同一生命周期表，统一显示审核中、已审核、不通过和已下架。
- 页面与平台接口不再提供操作记录、系统任务、渠道运行余额、行内测试和余额刷新；用户模型调用、消费、退款、渠道日志及结算账本仍完整保留。

所有管理员写操作都要求有效管理员会话和同源请求。普通用户、商户和匿名请求直接访问管理员接口时仍由后端鉴权拦截，前端导航隐藏不是权限边界。

## 发布验证工具

### 商户申请验收

`deploy/scripts/verify-merchants.sh` 不再让唯一管理员提交商户申请。脚本通过 103 内网的 New API 原生管理员接口创建一次性普通用户，由该用户经过 ModelRoute 公网接口提交申请，再由管理员会话读取并驳回；结束时通过 New API 原生接口删除临时用户。管理员、普通用户和 New API 管理会话使用独立 Cookie 文件，脚本不输出账号密码或渠道密钥。

### 运营只读验收

```sh
ADMIN_PASSWORD_FILE=/opt/modelroute-platform/shared/bootstrap-admin.txt \
  deploy/scripts/verify-operations.sh https://aggregate.lwylink.xyz
```

脚本只登录、读取用量与管理列表并退出，不创建兑换码、任务或渠道操作，也不输出管理员密码和 SMTP 密码。

### 只读压力测试

```sh
REQUESTS=200 CONCURRENCY=10 MAX_P95_SECONDS=1.000 \
  deploy/scripts/load-test.sh http://127.0.0.1:28100
```

脚本只请求 `/api/health/ready`，默认 200 次、并发 10，最大允许 10000 次和并发 200；任一非 `200`、请求缺失或 P95 超限都会失败。平台对数据库、Redis 和 New API 的就绪探测使用 1 秒共享结果，合并同一秒内的并发检查，避免监控和压测自身触发 New API 状态接口限流。

### 备份恢复演练

```sh
CONFIRM_RESTORE_DRILL=MODELROUTE_RESTORE_DRILL \
  deploy/scripts/verify-backup-restore.sh /opt/modelroute-platform/shared/backups/BACKUP_ID
```

演练先校验 `SHA256SUMS`，再把两个转储分别恢复到自动生成的临时数据库，检查表和平台迁移后删除临时数据库。生产平台库和 New API 库不会作为恢复目标，服务无需停机。

### 受控版本回滚

```sh
CONFIRM_ROLLBACK=MODELROUTE_ROLLBACK \
  /opt/modelroute-platform/current/deploy/scripts/rollback-release.sh RELEASE_HASH
```

脚本只接受 7 至 40 位小写 Git 哈希，验证目标是 `releases/` 的实体子目录且包含环境、Compose、部署和验收文件。目标部署与基础验收通过后才原子切换 `current`；失败时保留当前指针并尝试重新部署上一版本。数据库结构不兼容时仍须使用对应发布前备份执行数据恢复。

## New API 候选契约

截至 2026-07-22，上游最高正式标签仍为 `v1.0.0-rc.21`，与生产固定版本相同。本阶段把该版本作为候选基线执行真实容器契约，并保留未来镜像复用入口：

```sh
deploy/scripts/verify-newapi-contract.sh

NEW_API_CANDIDATE_IMAGE=REGISTRY/NEW_API:TAG@sha256:DIGEST \
  deploy/scripts/verify-newapi-contract.sh
```

候选环境使用独立 PostgreSQL、Redis、New API 和本地伪上游，New API 只绑定 `127.0.0.1:33100`，数据库与 Redis 仅在内部网络。契约覆盖初始化、管理员登录、用户创建/查询/删除、令牌创建/读取、渠道创建、模型映射、分层表达式、Chat、Responses、New API 原生 Embeddings、流式响应、缓存用量日志、退款日志结构和无渠道 `503`；结束后删除临时容器、网络和卷。Embeddings 仅用于验证固定 New API 核心未被外围改动，ModelRoute 公网不开放 `/v1/embeddings`。

本地候选契约通过只证明适配当前固定版本，生产发布结果以部署后的只读验收、压力测试、恢复演练和回滚演练记录为准。
