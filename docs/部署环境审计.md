## 业务结论

`38.34.191.101` 至 `38.34.191.105` 是同一台 Ubuntu 主机上的多个公网地址，并非五台独立服务器。ModelRoute 使用 `38.34.191.103` 对外承载域名，但运行环境必须和现有 Sub2API、SDK 服务隔离。

## 当前环境

- 操作系统：Ubuntu 24.04.1 LTS。
- Docker：29.6.2；Docker Compose：5.3.1。
- 根磁盘：469 GB，审计时使用约 12 GB。
- 内存：31 GiB，审计时可用约 29 GiB。
- 现有容器：Sub2API、Sub2API PostgreSQL、Sub2API Redis。
- 现有网关：宿主机 Caddy，占用公网 80/443。
- 现有域名：`api.lwylink.xyz`、`sdk.lwylink.xyz`。
- 审计时 `aggregate.lwylink.xyz` 尚未写入 Caddy 配置，因此 Cloudflare 回源出现 525；第 2 阶段已完成站点接入并恢复 HTTPS。

## 部署落点

- ModelRoute 独立目录：`/opt/modelroute-platform`。
- ModelRoute 容器使用独立 Compose 项目名、网络、数据库、Redis 数据前缀和数据目录。
- 平台网关只绑定 `127.0.0.1:28100`，宿主机 Caddy按域名反向代理，避免争用 80/443。
- 修改 Caddy 前必须备份原配置，执行 `caddy validate` 后只做平滑 reload。
- 不读取或迁移 Sub2API 的用户、渠道、余额和业务数据。

## SMTP 复用

Sub2API SMTP 设置存储在其 PostgreSQL `settings` 表。已只读确认：

- 服务商：阿里云邮件推送 SMTP。
- 端口：465。
- TLS：启用。
- 发件名称：LwyLink。
- SMTP 密码：已配置，审计输出中未显示。

实施时通过 New API 原生 `/api/option/` 管理接口写入 SMTP 字段，配置由 New API 设置数据库保存，不进入 ModelRoute `.env`。密码不得进入命令输出、仓库、文档或前端接口；New API 数据库备份按敏感文件管理。
