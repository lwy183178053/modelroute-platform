# ModelRoute 公告管理

## 业务规则

- 公告正文只按纯文本保存和展示，不解析 HTML。
- 公告受众可同时选择普通用户、商户和管理员。
- 当前账号只归入一个受众：普通商户只接收商户公告；唯一管理员只接收管理员公告，不重复接收商户公告。
- 公告支持草稿、定时发布、已发布和已下架四种状态。
- 定时公告到达 `publish_at` 后自动进入用户可见范围，不依赖后台任务修改状态；超过 `expires_at` 后自动隐藏。
- 已读记录以“公告编号 + 用户编号”为唯一键，重复标记保持幂等。

## 用户接口

- `GET /api/announcements`：返回当前账号可见的有效公告、单条已读状态和未读数量。
- `POST /api/announcements/{id}/read`：把当前账号可见的单条公告标记为已读。

读取公告要求有效平台会话。标记已读还要求同源写请求；已下架、已过期、尚未到发布时间或受众不匹配的公告统一按不可见处理。

## 管理员接口

- `GET /api/admin/announcements`
- `POST /api/admin/announcements`
- `PUT /api/admin/announcements/{id}`
- `POST /api/admin/announcements/{id}/publish`
- `POST /api/admin/announcements/{id}/withdraw`

新建公告未填写发布时间时保存为草稿，填写未来时间时保存为定时发布。草稿和定时公告可编辑；已发布公告先下架，不直接覆盖线上版本。发布草稿时立即写入当前时间；发布带未来时间的定时公告时保留原计划时间。

创建、编辑、发布和下架都要求唯一管理员会话和同源请求；公告记录自身保存创建人、状态与更新时间。

## 页面交互

- 顶部铃铛显示未读角标，打开后显示当前有效公告。
- 打开公告详情时调用已读接口，未读数量同步减少。
- 头像区域显示昵称首个汉字、字母或数字及当前身份，不展示下拉图标，也不绑定跳转行为；原无行为帮助按钮已删除。
- 管理后台侧栏增加“公告管理”，可创建、编辑、发布和下架公告。

## 数据结构

- `announcements` 保存标题、纯文本正文、受众位图、置顶、发布时间、下架时间、状态和操作人。
- `announcement_reads` 保存公告编号、用户编号和首次已读时间，联合主键保证幂等。
- 用户可见查询同时校验受众、状态、发布时间和下架时间，并按置顶、发布时间和编号倒序返回。
