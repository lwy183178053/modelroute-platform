# ModelRoute 账号与管理员接口

## 职责边界

- New API 保存账号、密码、角色、状态、额度、API 密钥和最终用量。
- ModelRoute 不直接修改 New API 用户表，只通过固定版本的原生接口完成读写。
- 浏览器只持有 ModelRoute 随机会话 Cookie；New API 会话仅保存在 Redis。
- 浏览器响应不返回上游 Cookie、管理凭据或内部商户资料编号。

## 账号和权限

| New API 角色 | 平台身份 | 页面权限 |
| --- | --- | --- |
| `1` | 普通用户 | 模型市场、控制台 |
| `10`、`100` 且用户名等于 `NEW_API_ADMIN_USERNAME` | 唯一管理员 | 普通用户页面、普通商户中心、管理后台 |

平台全局只承认 `NEW_API_ADMIN_USERNAME` 指定的一个管理员账号。其他账号即使在 New API 中带有 `10` 或 `100` 角色，进入 ModelRoute 后也按普通用户处理。管理员拥有一条真实的“ModelRoute 官方”商户资料，使用与普通商户完全相同的商户页面、接口和操作，只额外显示管理后台。前端导航只负责展示，所有平台接口仍在服务端校验账号状态和最低角色。

普通商户和唯一管理员进入商户中心后均使用经营概览、渠道管理、上架模型、调用记录和提现记录五个入口。两种账号不按角色分支渲染商户功能，渠道、模型、调用和提现由服务端根据登录用户解析归属；`/api/me` 只返回用户 ID、账号类型和商户状态，不返回内部商户资料编号。

用户控制台的“账户设置”采用双栏资料布局：左侧显示头像、用户 ID、当前工作区和对应入口，右侧按独立行显示登录账号、邮箱和用户类型；移动端自动上下排列，账号资料保持独立行高，不与身份摘要或工作区操作混排。申请商户审核中的提示和驳回原因固定显示在账号资料下方。

所有列表的“操作”列统一使用三点折叠菜单。菜单打开后显示当前行可用动作，危险动作使用红色标识；点击菜单外部、按 `Esc` 或改变窗口尺寸会关闭菜单。操作菜单采用固定定位，表格横向滚动时不会被裁切，移动端也保持单行高度。

高记录量列表统一显示分页栏，默认每页 `20` 条，可切换为 `50` 或 `200` 条，并提供首页、上一页、下一页和尾页。用户调用记录、商户调用记录、充值订单、用户列表、管理员渠道调用日志和提现审核使用接口的 `p`、`page_size`、`total`、`items` 字段进行服务端分页；模型市场在当前搜索、厂商和排序结果上分页，筛选条件变化时回到第一页。

顶部右侧身份摘要显示账号昵称和身份文案。头像从昵称中提取第一个汉字、字母或数字；身份文案继续使用“管理员 / 商户 / 普通用户”。身份摘要为静态展示，不承担控制台跳转，控制台入口通过主导航进入。

## 会话流程

1. 登录请求由 ModelRoute 转发到 New API。
2. New API 的 `session` Cookie 写入 Redis，不返回浏览器。
3. 浏览器收到 `HttpOnly + Secure + SameSite=Strict` 的平台 Cookie。
4. `/api/me` 每次向 New API 刷新角色、状态和额度，并再次按唯一管理员用户名归一化角色；账号被封禁或上游会话失效时清理平台会话。
5. 封禁用户或由管理员重置密码后，清理该用户的全部平台会话。

客户端来源 IP 经网关校验后传给 New API，供其登录审计和 IP 限流使用。

## 已开放接口

### 登录和账号

- `POST /api/auth/login`
- `POST /api/auth/login/2fa`
- `POST /api/auth/register`
- `POST /api/auth/email-verification`
- `POST /api/auth/password-reset/request`
- `POST /api/auth/password-reset/confirm`
- `POST /api/auth/logout`
- `GET /api/me`

密码重置确认成功后，New API 直接生成并返回新密码。页面只在当前重置弹窗展示一次，用户可立即复制。

### API 密钥

- `GET /api/keys`
- `POST /api/keys`
- `PUT /api/keys/{id}`
- `POST /api/keys/{id}/status`
- `POST /api/keys/{id}/reveal`
- `DELETE /api/keys/{id}`
- `PUT /api/keys/{id}/routing-policies`
- `GET /v1/usage`

控制台侧栏拆分为账户概览、路由管理、API 密钥、调用记录、充值中心和账户设置。创建密钥必须提交六个固定厂商之一的 `provider`，`routing_policy_ids` 可以为空；一把密钥可以为同厂商多个模型分别选择一条路由。密钥列表返回厂商、已配置模型数和模型路由列表，模型路由通过完整列表替换。

路由接口为 `GET|POST /api/routing-policies` 和 `GET|PUT|DELETE /api/routing-policies/{id}`。每条路由固定一个厂商和模型，同一模型可创建多套规则；平台只提供智能路由，不再维护固定商户名单。服务端校验路由、模型和密钥归属及厂商一致性，创建密钥后的绑定失败会清理刚创建的核心密钥。删除路由会自动解除全部密钥绑定，不删除密钥。

密钥正文、额度和生命周期仍由核心服务保存。平台数据库只保存 Token 编号、不可逆指纹、固定厂商和模型路由绑定，用于请求鉴权与候选解析；浏览器不会收到内部模型别名。密钥列表只返回掩码，用户点击复制时由 `POST /api/keys/{id}/reveal` 校验密钥归属并按需读取一次真实公开密钥，响应使用 `Cache-Control: no-store`。停用密钥保留平台绑定和模型路由，仍可在控制台查看、复制、重新配置或启用，但不参与实际调用；删除密钥时删除平台绑定，历史调用记录继续保留。

核心服务的密钥创建响应不包含 Token 编号，平台需通过创建前后的账号密钥列表识别新增 Token。当前单 `platform-api` 实例会串行执行“读取旧列表、创建密钥、读取新列表和保存路由绑定”，避免同一实例内的并发请求互相认领 Token；部署时保持一个 `platform-api` 实例。

密钥操作菜单支持一键导入 CC Switch。用户必须从当前密钥已经绑定的模型中明确选择默认模型，确认后页面才按需读取完整密钥并生成自定义协议链接；没有模型路由的密钥保持禁用提示。`GET /v1/usage` 使用 Bearer 密钥查询所属账户实时人民币余额，空路由密钥也可查询，响应不返回账号资料、密钥正文或路由信息。具体参数和错误语义见 `docs/CC Switch接入.md`。

账号余额按人民币显示：核心页面余额 `1.00` 等于平台 `¥1`。平台从核心状态读取实际 `quota_per_unit`，浏览器录入人民币金额，服务端接口继续使用换算后的整数额度。

### 管理员

- `GET /api/admin/users`
- `GET /api/admin/users/{id}`
- `POST /api/admin/users/{id}/status`
- `POST /api/admin/users/{id}/quota`
- `POST /api/admin/users/{id}/password`
- `POST /api/admin/users/{id}/merchant-status`

用户列表支持按 `user`、`merchant`、`admin` 类型筛选。商户身份的撤销与恢复并入用户管理，不再维护独立商户权限列表。额度调整支持增加、扣减和覆盖三种模式，管理员按人民币录入，平台转换为核心整数额度。管理员重置密码时会保留目标用户的账号、显示名称、分组和备注。

## 运行配置

- `PUBLIC_ORIGIN`：浏览器公开来源，用于写操作来源校验。
- `SESSION_COOKIE_NAME`：平台会话 Cookie 名称。
- `SESSION_COOKIE_SECURE`：生产环境必须为 `true`。
- `SESSION_TTL`：平台会话有效期。
- `NEW_API_REQUEST_TIMEOUT`：账号类 New API 请求超时。
- `NEW_API_ADMIN_USERNAME`：ModelRoute 唯一管理员用户名，同时也是管理员直属官方商户的归属账号。

上述变量只包含账号服务配置。平台数据库密码和后续支付密钥保存在服务器受限环境文件中；SMTP 配置通过 New API 原生管理接口写入其设置数据库，不写入平台 `.env`。New API 数据库备份按敏感文件管理，SMTP 密码不得进入 Git、平台接口或浏览器。

## 本地 V2 验收

- 管理员登录、类型化用户列表、密钥创建、复制、启停、删除和退出均由本地契约覆盖。
- 已删除的密钥查看、操作记录和系统任务路由由服务端测试确认不再注册。
- 封禁、解封、额度调整、密码重置和商户身份变更均通过平台接口执行，平台不直接修改核心用户表。
